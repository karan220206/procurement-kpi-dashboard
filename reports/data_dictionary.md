# Data Dictionary — Raw Procurement Data

Synthetic procurement records for an Indian manufacturer, **Jan 2023 – Dec 2025**, generated by
`src/generate_data.py` (seed 42, so re-running it gives identical files).
All money is in **INR**. Files are UTF-8 CSVs in `data/raw/`.

| File | Rows | Grain |
|------|------|-------|
| `vendors.csv` | 155 | one row per vendor record |
| `items.csv` | 800 | one row per item (SKU) |
| `purchase_orders.csv` | 51,000 | one row per PO line |
| `deliveries.csv` | 54,493 | one row per goods receipt (a PO line can be received in 2 shipments) |
| `sales.csv` | 28,944 | one row per item per month (consumption) |
| `inventory.csv` | 1,600 | stock per item at two snapshots: 2022-12-31 (opening) and 2025-12-31 (closing) |

## Relationships

```
vendors (vendor_id) ──< purchase_orders (vendor_id)
items   (item_id)   ──< purchase_orders (item_id)
purchase_orders (po_id, line_no) ──< deliveries (po_id, line_no)
items   (item_id)   ──< sales, inventory
```

## vendors.csv
| Column | Type | Description |
|--------|------|-------------|
| vendor_id | text | Vendor code `V001`… |
| vendor_name | text | Registered name |
| category | text | Main supply category (7 categories) |
| city, state | text | Vendor location |
| onboarding_date | date | Date the vendor was approved |
| payment_terms | text | Net 15 / 30 / 45 / 60 / Advance |

## items.csv
| Column | Type | Description |
|--------|------|-------------|
| item_id | text | Item code `I0001`… |
| item_name | text | Description, e.g. "TMT Bar 12mm" |
| category | text | Raw Materials, Packaging, Electrical & Electronics, MRO, IT Hardware, Chemicals, Office Supplies |
| unit_of_measure | text | tonne, kg, piece, metre, litre, roll, box, ream, pair |
| standard_price | money | Standard cost per unit, set at the start of 2023 |

## purchase_orders.csv
| Column | Type | Description |
|--------|------|-------------|
| po_id, line_no | text, int | PO number and line number (together = unique line) |
| order_date | date | Date the PO was raised |
| vendor_id, vendor_name | text | Supplier as recorded on the PO |
| item_id | text | Item ordered |
| quantity | int | Quantity ordered (in the item's unit of measure) |
| unit_price | money | Agreed price per unit |
| order_type | text | Regular / Bulk / Urgent |
| promised_date | date | Delivery date promised by the vendor |
| buyer_id | text | Procurement team member `B01`–`B12` |

## deliveries.csv
| Column | Type | Description |
|--------|------|-------------|
| delivery_id | text | Goods-receipt number `DL000001`… |
| po_id, line_no | text, int | PO line being delivered |
| received_date | date | Date goods were received |
| qty_received | int | Quantity received in this shipment |
| qty_rejected | int | Quantity rejected at quality inspection (blank = none recorded) |

PO lines with no delivery were still open at the 2025-12-31 cut-off.

## sales.csv
| Column | Type | Description |
|--------|------|-------------|
| item_id | text | Item |

## inventory.csv
| Column | Type | Description |
|--------|------|-------------|
| item_id | text | Item |
| snapshot_date | date | 2022-12-31 or 2025-12-31 |
| qty_on_hand | int | Stock on hand at that date |

## Known data-quality issues (to fix in Phase 3)
These are typical of procurement data exported from an ERP and merged with spreadsheets:

- **Duplicates:** repeated rows in purchase orders, deliveries and sales; the same supplier registered twice under different vendor codes
- **Vendor names:** inconsistent case, spacing and suffixes ("Pvt Ltd" / "Pvt. Ltd." / "Private Limited"); some PO lines have no vendor_id
- **Dates:** three formats mixed together (`2024-03-05`, `05/03/2024` = DD/MM/YYYY, `5-Mar-24`); some missing; some receipts dated before their order
- **Prices:** some stored as text with ₹ and thousands separators; a few entered in paise (×100); a few missing
- **Quantities:** some zero or negative quantities; some rejected quantities larger than received; negative stock values
- **Categories and codes:** inconsistent casing and trailing spaces in category, order_type and state (including state codes like `MH`)
- **Referential problems:** some receipts point to PO numbers that don't exist; months written as `Mar-2024` instead of `2024-03`

## Ground truth (`data/truth/`)
`data/truth/` holds the same tables *before* the problems were injected, plus the hidden vendor and
item traits used to simulate behaviour. It is **not** used for the analysis. Its only use is
checking cleaning accuracy at the end of Phase 3 (e.g. "the cleaned data matches the true data on 99.x% of lines").
